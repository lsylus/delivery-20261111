# B11 planar manufacturing topology

B11 consumes the B10 Panel outer ring, real hole rings, world right-handed frame and source references. B10 selection/baseline/allowance/surfaces/openings/volume/checks/pipeline stay byte-identical to the independently reviewed implementation. No evaluation closure enters a net. The supported production input remains B10 regular planar box covers, including openings and excluded panels. The kernel also handles individual nonrectangular planar domains and full-edge planar forests; curved surfaces, T-junction subdivision and arbitrary assembly coverage belong to B13.

## Coordinates and identifiers

Panel UV is actual millimetres in its original face frame. `key` is the B10 stable side (`x-`, `x+`, `y-`, `y+`, `z+`); generic planar input uses its panel ID. Current `panel_id` remains revision-specific. Edge IDs are `<key>/e<outer-loop-index>`; seam ID is the sorted pair of edge IDs joined with `~`. Pairing compares world endpoints with 1e-6 mm numerical tolerance and rejects nonmanifold matches. Hole edges remain opening cuts, never inferred joining seams. No bottom Panel is synthesized.

Each connected fold forest produces a piece. Each piece exposes its complete unioned `material_domain` (GeoJSON Polygon/MultiPolygon, holes retained) and `material_area_mm2`. A piece stores per-panel orthogonal 2D rotation/reflection and translation (`transform`), net outer/hole coordinates, front/back, and a separate `layout {translation_mm, rotation_rad}`. Layout acts only when producing the DrawingDocument; no scaling is exposed and it never enters foldback, engineering areas or cover volume. `mapping_ref` binds revision, panel, seam configuration and rigid maps. World positions are reconstructed from net coordinates through the inverse piece map and the original face frame, including hole vertices and edge pairing. Native `folded-body.brep`, `flat-body.brep` and `folded-tabs.brep` are reconstructed from these domains and read back in acceptance.

## Explicit cut / fold / join semantics

`blanket.unfold {result_id, settings?}` accepts `base_panel`, optional explicit `fold_seam_ids`, `cut_seam_ids`, `seam_overrides`, and `layouts`. Omitting folds selects a deterministic breadth-first forest rooted at the chosen panel (top by default); this produces the familiar five-square cross only for that topology. An explicit empty fold list means separate pieces. Explicit cycles are rejected with the involved seam and cut candidate; planar overlap returns location and candidate seam cuts. The code never silently removes an explicit fold.

A `fold` connects the net and has no overlap owner, width=0. A `cut` is a paired but deliberately unjoined boundary with no owner, width=0. A `join` is cut in the flat material and paired for assembly, with exactly one owner and positive width (default 15 mm). `blanket.edit_seams {result_id, seams:[{id,kind,overlap_owner_panel,width_mm}]}` changes those decisions explicitly. Unpaired edges, duplicate seam edits and foreign owners are rejected. All IDs are returned by the net, not inferred from GLB triangles.

Full-width rectangular tabs extend perpendicular to the directed owner edge in that panel's plane. The corresponding full strip lies inside the receiving panel. We check owner material, receiver exterior and holes, flat panel/tab intersections, and overlapping folded strips at corners. Conflicts return seam/panel IDs, the exact intersection geometry, explicit coordinate space, full-width change-owner preview polygons, a 2D location (piece coordinates for flat collisions, receiving UV for folded conflicts), and explicit change-owner/change-width/cut candidates. Width is never shortened, mitered or clipped automatically. A simple rectangle tab policy is deliberately explicit; manufacturing corner solutions requiring a chosen cut must be selected by the caller. Body, openings and overlap areas are separate. B10 enclosed-volume checks are copied from a fresh B10 rebuild; extra cloth never changes the denominator or evaluation solid.

## Fixed points and revision transactions

`blanket.edit_fixed_points {result_id, command}` supports add `{action,id?,panel_key,uv_mm}`, move `{action,id,panel_key,uv_mm}`, delete `{action,id}`, and spacing `{action,panel_key,start_uv_mm,end_uv_mm,spacing_mm}`. Positive finite spacing samples the specified segment from its start; the end is included only when it lies at an integer interval. Every sampled point must be valid or the operation fails atomically. The limit is 10,000 active points. IDs omitted by callers are server UUIDs reserved in the immutable candidate revision before work starts. An explicit ID cannot be reused after deletion, failed work, undo, branching or restore: reservations are collected from all same-project blanket revisions, not just the current head.

A point belongs to actual body plus owned tab material, excluding holes and notches. A selected face point on an internal retained fold is valid; after cutting that fold it is rebound and explicitly invalidated if it becomes a material boundary. A point within 1e-6 mm of the material boundary is explicitly rejected (`point_on_material_boundary`); this is a numerical boundary policy, not a manufacturing margin. Tab points map onto the receiving panel when folded. No fixed count, normalized bounding box or fabricated clearance requirement is used. Recutting, base changes and owner changes rebind surviving IDs from stored panel UV; points outside the new material become `needs_reselection` with an invalid mapping reference and the candidate fails. The old valid revision remains current, so the caller can move/delete the identified point and retry. Shape edits invalidate the entire old net, retain ID reservations, and require unfolding anew.

HTTP does no OCP computation. Existing owner/session/project checks, idempotency, revision CAS, worker cancellation, leases, atomic publication and late-result history apply. Net commands create a candidate revision containing a single server-owned `blanket_net_v1` entry in `document_edits`. Direct injection through revisions is prohibited. Failed candidates never replace the last good result. Current results are served by `GET /projects/{id}/blanket-net`; the existing blanket-result route remains B10-compatible. Net JSON, native face geometry and DrawingDocument share one revision.

`b11-state-v1` bundles keep full net result, canonical fixed points, seam/cut decisions, editable drawing and original model/derived asset references. On restore the server checks source and asset hashes, reconstructs B10 from source BRep, then replays persisted B11 state with the same point identities and a new revision/mapping. Historical B06/B09/B10 bundles remain readable. The model bundle `cut_edges` now accepts either historical EntityRefs or B11 derived seam ID strings; consumers must discriminate the type. No offline transfer or external DWG-to-3D reconstruction is promised.

## Drawing and numerical checks

The DrawingDocument emits distinct CUT, FOLD, OVERLAP, FIXING and DIMENSION layers, actual lengths and original source refs. The owner tab root is an overlap line; the other three tab sides are cuts. Hole rings are cut polylines. Packing includes tab extents and translates pieces with a default 50 mm drawing gap; it is not a manufacturing margin. B11 acceptance reads editable DXF entities back, but does not claim B12 UI or final DWG/AutoCAD acceptance.

Length oracle 1e-6 mm, polygon intersection area threshold 1e-7 mm2, frame orthogonality 1e-9; no business contact threshold is repurposed. Tests include damaged net and hole vertices to ensure foldback checks do not merely copy source geometry. B11 independent review remains pending after execution; B04 AutoCAD, B05 native conversion, B07 formal DSH and B09 engineering truth/full acceptance remain blocked where previously recorded.

B11 seam `overlap_owner_panel`, edge `panel`, tab owner/target and point `panel_key` reference mapped Panel.key. Panel.id and FixedPoint.panel_id remain the exact revision-specific IDs. This is a new net interface; callers must not interchange these keys with FaceRef or source entity IDs.

The retained B10 BlanketResult.downstream fields describe its cover-only producer stage, not project-wide B11 availability. B12 must query the current blanket-net endpoint and match revision_id; a cover result alone is not proof that a current net exists.
