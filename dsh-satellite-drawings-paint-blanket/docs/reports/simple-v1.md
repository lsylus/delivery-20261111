# 多层包覆插件简化版：使用说明与验证结果

更新日期：2026-11-09。需求依据：`docs/simple-v1-requirements.md`。

本版已完成三个小样例的实际界面流程和 OpenCADStudio DWG 检查，可以试用。约 671 MB 的真实整星 STEP 首轮导入在 900 秒限时内未完成；第二轮优化后进入原生读取、转换与 BRep 写出阶段，随后定位到原生空网格面及显示质量检查主动拒绝情况，不能将所有失败统称为零面积。最新全模型冷测仍待结果。整星导入及其三维直接选件、选安装面尚未完成验收，因此本版整体验收仍未完成。

## 打开界面

5090 上的试用工作台地址为 **http://127.0.0.1:18890/**。进入后点击左侧 **“多层图纸”**，打开“多层包覆图纸”插件。直接访问根地址会建立当前试用会话，不需要手填令牌。

该地址只监听 5090 本机回环。如果浏览器运行在自己的电脑上，先建立 SSH 端口转发：

```sh
ssh -N -L 18890:127.0.0.1:18890 5090-qmh
```

然后在电脑浏览器打开同一地址。当前入口使用真实插件注册和构建产物，宿主为隔离试用环境；正式 DSH 宿主中的身份与会话接入仍需按目标环境配置和验证。

如需在源码目录重新启动当前试用环境：

```sh
.venv/bin/python scripts/start_simple_trial.py --port 18890 \
  --converter-config deploy/opencadstudio-5090.json --background
```

启动前应确认没有同一试用实例占用端口。私有运行状态保存在 `work/simple-v1-trial/`，不随交付包分发。

## 一次包覆出图

1. 新建工程，导入 STEP；模型就绪后直接在三维画面选择要包覆的部件，再选一个平面作为安装面。圆柱侧面不能作为安装面。模型方向给定平面内方向，可按界面预览反向或旋转。
2. 选择方形罩或圆柱罩。底部安装面敞开，包覆侧面和顶部。默认放量系数 1.05，分别增加方形罩长宽高、圆柱罩直径和高度，安装底部位置固定；界面显示实际尺寸。
3. 在三维画面选独立小部件并标记“不包覆”。它不再撑大罩壳，在穿出顶部等受支持平面的位置生成开口，三维中仍保留该小部件。组合样例中选择独立小圆柱后，方形罩顶部生成一个圆孔。单一实体上的凸台不会自动拆分成独立部件。
4. 生成罩形、查看开口，展开二维裁片，再调整搭接宽度、固定点和文字注释。搭接独立于 1.05 尺寸放量。保存工程包可保留参数与人工修改；重新打开或恢复后应使用当前版本生成出图。
5. 点击 **“导出并预览 DWG 草稿”**。验证成功的 DWG 和真实 OpenCADStudio 软件 PNG 由同一次导出运行提供；可以直接预览和下载。可选软件预览失败时会提示不可用，已验证 DWG 保留。

主界面以三维直接选择为主，不要求按部件编号或列表操作。首轮支持方形罩平面与圆柱罩顶部平面的开口；圆柱侧面、跨多个罩面的开口和一体特征自动识别不属于本轮已验范围。

## 裁片数量与参考值

裁片是实际独立裁切制作的片料，按 **一个对象、每层分别** 计数，默认上限 10，可调整。同层两片形状相同仍计两片；三层每层四片显示总制作数量十二片。超过当前上限时保留可查看方案并明确提示，不自动突破上限。

体积比参考值与裁片上限分别处理。超过体积比参考值会提示，但可由用户采用常规罩方案；1.05 是线性尺寸放量，不能当作体积比。内部几何复杂度和计算资源另有限制。

## 部署与安装包

交付准备包括插件 npm `.tgz`、已提交源码归档、三个 STEP/DWG 样例、原始软件 PNG 和验证说明。插件包由 `plugins/blanket/plugin/package.json` 的构建与打包流程生成，包含 `lib/`、`public/`、`mcp/` 和 `cordis.patch.yml`；通过目标 DSH 支持的插件包安装/加载机制接入，并注册“多层图纸”入口。后端服务地址和隔离身份解析由宿主部署者配置，不能只复制静态页面就视为完整安装。

源码部署需要锁定的 Python、Node、原生 CAD 依赖及相应构建环境。当前 5090 的依赖运行时、`.venv`、`node_modules`、私有会话和大型输入文件不在源码归档中；应按 `uv.lock`、`package-lock.json` 重建并构建插件，再启动后端与宿主。当前现成路径配置位于 `deploy/opencadstudio-5090.json`，换机器时需调整绝对路径。

OpenCADStudio 使用独立安装的官方 v2026.45 原生软件，不内嵌在插件 npm 包里。当前安装在 `/data/qmh/OpenCADStudio/`；DWG 配置指向其 `current/squashfs-root/usr/bin/OpenCADStudio` 原生程序。每次导出使用独立 `--serve` 会话，预览使用隔离 Xvfb 与官方 MCP，不修改共享软件配置。详见 `docs/architecture/opencadstudio-output.md`。

打包前可运行 `.venv/bin/python scripts/package_simple_delivery.py --check` 仅检查素材和源码状态。正式打包应在改动收敛并提交后执行；本说明编写阶段尚未运行打包。

## 大模型性能与源几何显示限制

首轮整星导入耗尽 900 秒限时。第二轮记录的原生读取约 49.97 秒、Transfer 约 242.62 秒、BRep 写出约 79.67 秒，随后在源近零面积面处失败；后续排查还发现其他原生网格生成失败情况。各面按诊断记录具体原因，不把显示失败都归为零面积，也不能简单归因于 Python 语言。

当前优化包括 NumPy 批量处理、原型缓存、按定义共享 GLB 网格并用各实例 node 矩阵定位，以及把面面积和质心的 GProp 计算合为一次原生积分。大模型显示采用 absolute 1.0 mm / 0.5 rad 离散配置；制造操作按当前选择限定加载原生几何，避免每次重载全部装配。最新大型显示网格计算使用 OCCT 原生四线程池；小模型保持原路径。

局部 5927 面基准中，large-only 1.0 mm / 0.5 rad 配置相对原生面积差约 0.00805%，三角形数量减少约 23.7%；这不代表已测得速度提升或整星覆盖。生产 Viewer 的实际 canvas 已验证两个实例共用一个 mesh 时仍能区分拾取，世界命中点误差约 0.000006 mm，未出现浏览器错误；记录见 `shared-viewer-result.json`。

完整原生 CAD、BRep 和 FaceRef 身份保留。未纳入显示的面记录在 `unrenderable_faces` 诊断目录，其中包括原生无网格和新增显示质量检查主动拒绝两类，不伪造三角形或可拾取范围。界面明确提示未纳入显示的面数与原始几何保留状态，用户只能从真实可见三角形中选择。诊断保留原生有效性和显示拒绝原因；当前目录中通用 reason 字段仍未细分两类，须同时检查 failure 与 source_triangles；显示可见不代表制造有效，制造路径的原生 `isValid`、面顺序与签名校验仍严格执行。

已完成的几何回归覆盖导入、映射和显示策略，不能替代整星冷测或制造验收。最新全模型冷测结果仍为 pending。只有最终 `work/simple-v1-evidence/final/satellite.json` 明确记录 `status: passed` 才能标为整星验收通过；失败、缺失或未完成记录均不算通过。

## 已知限制与未完成项

- 671 MB 真实整星经历首轮 900 秒超时，后续发现源退化和其他网格失败面；当前全模型冷测待结果，三维选件、选安装面的验收仍未完成。未要求整星全部包覆出图，但不能省略本项导入/选择验收。
- 软件原始视口为 729 × 579，总图中的文字较小；部分反向边尺寸文字朝下，CPU 渲染通知与命令条会占用底栏。真实局部视图能读清中文、105/84 mm 尺寸和组合圆孔，未为展示而修改 DWG 字体或颜色。
- OpenCADStudio 官方 verified-save 与软件打开检查通过；原始反转 DXF 附带 owner 为零的 TABLESTYLE。原始文件保留，仅在明确记录的辅助验证副本中去掉这些非图形记录；DWG 未修改，其他修复仍拒绝。
- 本轮为执行侧的真实软件检查，尚无独立 AutoCAD 编辑/保存/重开证明，也不等于工程制造批准。
- 更贴形的复杂拟合、球形、圆柱侧面/跨面开口以及一体特征自动拆分留待后续。

## 最新核查补充：显示过滤与原生网格失败

按用户指示，暂缓追求 671 MB 首次导入 15 分钟指标。对照几何插件及同一 BRep 的三档实测，23 个面三档原本均无网格，另有 6 个原本有网格的面被新增显示质量检查主动排除（仅三个定义范围）。因此未显示面不能全部称为源模型缺陷或原生无法网格化。制造检查未放松，当前显示过滤策略尚未改变。完整证据、范围与限制见 `step-import-comparison.md`。整星可用性仍未宣称通过。

## 本轮继续：原生裁片与定位标记

当前优先完成真实模型的原生裁片到 DWG 链路，整星 15 分钟耗时指标暂不验收，亦不能据此宣称整星已可用。新增复合外形裁片、特征标注与定位点拖动保存仍须用最新真实界面产物验证，不沿用旧单罩样例结论代替。

定位点是位置标记，不是钻孔。验证将比较拖动前后的持久定位点 ID、面内与排版坐标、源 DrawingDocument，以及实际原生 DWG 中的 POINT；移动定位点不应改变 CUT 轮廓。轮廓、特征名称、尺寸和中文需随同当前工程版本出图，并在真实软件中重开查看。

裁片上限默认仍为每层 10 片；若当前真实展开需要更多，须由用户调整上限，并明确显示实际每层数量和多层总量。基础几何体数量不等于独立裁片数，不能把“8 个基础体”写成“8 张裁片”。

执行侧证据脚本为 `scripts/audit_native_dwg_points.py`：接收最新前后 NetResult 与同版本 UI 导出 DWG，隔离重开并反转实际 DWG，检查 1e-6 mm 坐标、标记身份、轮廓未改和文字/尺寸保留。它不重新生成罩形，不替代最终人工工程确认。
