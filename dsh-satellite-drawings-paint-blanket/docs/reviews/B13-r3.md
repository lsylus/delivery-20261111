## 决定性发现

**[高] 从零选择安装底面生成的框架与通过候选不同，且 UI 无法调整。** `installationFrame` 对实际 44 面 motor 的唯一底面 `face-4` 生成底面中心原点和世界 `-Y` 的局部 X 轴；通过的 HTTP 候选使用最小角原点和世界 `+X`。工作台没有安装原点/X 轴旋转控件，R3 浏览器用例又直接从 HTTP 预建状态开始。

该差异有可执行反例：新 UI 框架的局部 X 范围为 `[-72.5000001, 72.5000001] mm`，预建的 `40/300/334 mm` 分段直接报 `invalid_native_section_cuts`。清空分段后罩形体积比 `1.6718582749`、状态 failed；使用最多 7 个均匀分段后体积比仍为 `1.4582995986`、状态 failed。故现有 UI 控件虽可计算合法右手 Z=0 框架，却未证明也不能重放受验的 `1.1304394985` 候选。证据见 [ui-from-zero-counterexample.json](../evidence/B13/r3-review/ui-from-zero-counterexample.json) 与 [ui-installation-frame.json](../evidence/B13/r3-review/ui-installation-frame.json)。

修复应让用户明确选择/旋转安装 X 轴和原点，或由服务稳定推导与受验方案等价的框架，并新增从导入 STEP、选底面、设置分段到生成通过罩形的浏览器场景。预建后保存/恢复不能替代此验证。
