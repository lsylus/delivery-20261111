## 执行步骤

1. 在干净隔离构建目录从锁文件构建前端、插件包和后端，产物中不存在旧绝对PYTHONPATH、开发密钥、真实样件或源仓库路径依赖。
2. 先在新数据目录/空闲端口完成单机安装、重启、备份恢复与卸载回归；停止/清理仅本批创建的进程和资源，记录资源ID。
3. 按宿主插件管理器实际规范安装两个新namespace到9999平台的隔离验收profile或等效隔离环境，检查登录态代理、MCP、会话切换和真实业务导出。
4. 验证无S/H服务或源码挂载也能导入STEP、生成两业务结果；商业转换依赖有可识别状态与配置说明，不能依赖旧热NX worker的私有默认。
5. 记录旧G/T代码HEAD/dirty、容器/端口状态与基线一致；新插件卸载不影响旧工作台。
6. 交付两插件包、后端包/镜像、部署配置模板、用户手册、支持矩阵、验收记录和回滚方法，更新最终进度。

## 可执行验收与通过条件

以下命令在NEW_ROOT、激活B01新环境后执行。新增脚本/测试由本批实现；不得用占位通过或空测试代替验收。

```bash
npm ci
npm run build --workspaces --if-present
python scripts/build_release.py --output dist
python scripts/smoke_release.py --manifest dist/manifest.json --config work/config/release.local.json
python scripts/verify_installation.py --target http://10.110.10.11:9999/ --profile-config work/config/host-test.local.json --report-dir docs/evidence/B15
python scripts/verify_batch.py B15 --report-dir docs/evidence/B15
```
