## 实现结果

- `build_delivery(revision, input_dxf, pages, original, output)` 只消费冻结 revision/`expected_row_ids` 及同一 B04 DXF/pages。正式 DXF 出口重新传入 revision，重载受控模板、重排版、读回和原子替换；PDF 按 `DrawingPage.placement` 从该汇总 DXF 裁切，未重算第二套几何。
- 每个单页必须真实为纵向 A4 单页；合并输入是 `expected_row_ids` 原行序显式列表，不 glob 目录。验证时从正式 DXF 和 fresh page plan 独立重渲染权威参考页，单页和合并页都必须与对应参考像素一致。
- 候选目录先在同文件系统隔离 staging 中构建。缺页/多页/损坏/错序/额外残留/路径逃逸/文件名冲突/hash 漂移/任一行渲染失败都在整体落位前失败，第 2 行注入失败实测不留目标候选目录。
- `original.xlsx` 保留原字节；`actual.xlsx` Sheet1 只有最终交付行和最终比例，`变更记录` 按源行保留并精确验证 row_id、源 Excel 行、原/最终比例、skip 原因、actor/time/receipt/revision；row report 精确保留逐行 issue 和 global issue。
- `manifest.json` 不自引用；ZIP 包含 manifest，外层 `run.json` 绑定 manifest/ZIP hash/bytes。manifest/run/Artifact 的 run、revision、row/page、路径、kind、MIME 做精确交叉绑定。DWG 明确为 `disabled_not_provided`，无空占位。B05 只产生 `verified_candidate`，B06 仍负责原子发布、访问控制和真实 Host receipt。

## API、错误码与 B06 交接

- 核心 API：`build_delivery(...) -> validation result`、`validate_delivery(directory, revision, template_dir) -> result`。候选文件只能通过 manifest 的明确相对路径和 `expected_row_ids` 读取。
- 主要失败码：`UNRESOLVED_ERROR`、`UNACCEPTED_PROPOSAL`、`EMPTY_DELIVERY_SET`、`PAGE_BINDING_MISMATCH`、`DXF_READBACK_FAILED`、`PDF_REFERENCE_FAILED`、`PAGE_CONTENT_MISMATCH`、`MISSING_ARTIFACT`、`ARTIFACT_SET_MISMATCH`、`HASH_MISMATCH`、`INVALID_PDF`、`PAGE_COUNT_MISMATCH`、`PAGE_SIZE_MISMATCH`、`PAGE_ORDER_MISMATCH`、`ROW_SET_MISMATCH`、`NAME_COLLISION`、`PATH_ESCAPE`、`INVALID_WORKBOOK`、`INVALID_ZIP`。
- skip 决定必须唯一覆盖该行并包含该行全部 skippable row error ID，且只能引用该行 skippable row issue；workbook/system 或 non-skippable error 不可被 skip。warning 保留在 revision/report，任一未覆盖 error 仍阻断。
- `run.json.state=verified_candidate` 不是 published。B06 必须在同文件系统事务中验证 generation token/revision/manifest+ZIP hash 后整目录发布，并用真实 Host 事件签发 actor/session/action/base revision/proposal 回执；不得接受 fixture 字符串。
