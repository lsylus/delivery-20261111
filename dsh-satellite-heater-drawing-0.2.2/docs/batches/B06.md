## 4. 接口、数据结构和兼容性约束

实现C04所有业务端点；缺人工确认的服务端不能接受布尔confirmed。先定义一次性receipt协议与测试Host issuer，真实DSH发行者由B07接入；测试issuer只在显式测试配置可用，生产模式拒绝它。

SQLite开启事务/合适busy_timeout，API与worker共用一个数据库，worker通过事务claim，默认一个worker并发。job/revision/run/decision/review/artifact独立表，revision不可变；optimistic revision_hash防并发确认误用。状态机按C03，running时新错误停止后续行；系统错误不可通过skip消除。

同一个Idempotency-Key+相同身份和payload返回原响应，不重复排队；同键不同payload返回409。取消令牌/lease和publish事务防迟到结果；进程重启不自动标成功。原子目录rename与DB发布之间崩溃要可恢复，未登记目录不可下载。

业务确认必须绑定当时问题/比例清单，重传新job；跳过新错误新revision；字段普通修改只能重传。候选诊断可保留但不能混入送审Artifact集合。下载使用artifact_id查询归属，拒绝跨会话、任意path/URL和目录遍历。readyz在模板/字体/DB未就绪时非200；DWG disabled不影响DXF模式就绪。

## 5. 可执行的验收步骤与通过条件

1. `.venv/bin/python -m pytest -q tests/api tests/jobs`：所有状态转换、409冲突、拒绝伪身份/receipt、idempotency、并发双start、全skip/不可skip、跨用户/会话下载与预览拒绝。
2. `.venv/bin/python scripts/smoke_service.py --mode isolated --case fixtures/case/加热器图纸.xlsx --output docs/evidence/B06/smoke`：脚本创建独立临时DB和测试服务/worker，真实执行三个案例、下载并用B05校验包，结束后清理自己的进程（不能停旧服务）。
3. 故障矩阵：初始第2条非法→未开始任何绘图；未确认scale→不排队；确认skip→剩余2页；运行第2张注入失败→停后续行、不发布；旧skip receipt重放拒绝；新skip生成新revision；修复重传不复用旧批准。
4. 中断测试覆盖写第1页、合并中、目录rename后DB提交前、发布事务后进程退出：重启无假成功/混合包；cancel与publish竞态不允许已取消run发布；retry使用新run且旧历史保留。
5. 验证临时缺字体/磁盘写失败给system error，不得提示跳过全部行解决；所有HTTP错误具有request_id但无令牌/内部敏感路径。
6. `.venv/bin/python scripts/verify_batch.py B06 --report-dir docs/evidence/B06`；OpenAPI快照与实际路由一致，所有真实e2e产物hash归档。

通过：无需前端也能通过严格API完整跑通，错误先暂停、用户确认可追溯，冻结集合无漏项，重启/并发/身份边界可靠。
