## 4. 接口、数据结构和兼容性约束

所有显示从C04接口获得，不在前端重算工程校验。刷新/切换会话清除旧订阅，返回新revision必须更新全部issues/proposals；旧响应不得覆盖新会话。用polling获取任务，先不引入WebSocket；退避并显示连接状态。

错误表显示sheet/原行号/code/字段/原因/修正建议；正常默认引导下载原表并修正重传。跳过按钮不预选任何行，用户逐项选中后展示确切清单及预计页数，再经可信Host确认。禁止“忽略所有错误”快捷路径绕过不可skip issue。

比例确认显示原比例、推荐比例、超框原因和实际尺寸不变提示；允许一次确认明确列出的多个proposal，不默认接受新proposal。人工确认失效返回409时重取状态并解释，不自动重发带新revision。

生成前摘要展示总行数、跳过数、预计出图数、实际比例变更；开始按钮在仍有错误/未决proposal时禁用，同时服务端仍强制校验。运行错误显示暂停，给修正重传/重试/明确跳过选项（按error scope控制）。只可预览完整送审包或明确标诊断的临时图，不能把部分页显示成完成。

生成完成显示“待工程复核”，有用户确认跳过时持续显示数量与原因；人工approved才显示已复核。PDF预览与下载都走artifact_id。图纸内容不因UI标记而擅自改版，加工前复核提示在工作台及报告体现。

## 5. 可执行的验收步骤与通过条件

1. `npm ci --prefix web`、`npm test --prefix web`、`npm run build --prefix web`；`npm run build --prefix plugin`。构建必须包含完整viewer；删除web/dist时发布打包检查失败，不发布空工作台。
2. 在真实测试DSH中使用原3行xlsx：成功上传→校验→生成→3张预览→合并3页→下载包→pending复核→人工记录approved，状态绑定当前hash。
3. `npx playwright test --config playwright.config.ts`（本批创建根端到端工具的package.json/package-lock.json并锁版本）：执行错误行、scale proposal、确认skip后少1页、重传后旧确认失效、409并发变更、生成失败/重试/取消、刷新恢复及会话切换。自动化receipt只用测试部署，不能生成生产批准。
4. 人工走查：不用开发者解释也能找到第几行哪个字段错误；跳过前后总数/页数一致；PDF合并缺页无法当成功下载；普通字段无网页偷偷改值入口。
5. 记录窄屏表格/键盘操作/中文长字段显示，不能为排版截断错误原因或待确认清单；截图对应确切revision。
6. `.venv/bin/python scripts/verify_batch.py B08 --report-dir docs/evidence/B08`；重新检查插件包没有凭据/用户材料，记录完整包hash。

通过：真实DSH内端到端用户流程可完成，确认是显式且可追踪，无法通过前端绕过完整性与权限；全部文案区分技术生成和工程复核。
