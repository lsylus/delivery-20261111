# B10 — 无 Docker 部署、回滚与移交

执行前阅读plan、contracts、project-baseline、B09报告与冻结候选、progress。

## 1. 目标与明确的不做事项

把通过验收的服务和插件以独立Python环境＋systemd部署到目标Linux/DSH，完成重启、备份、升级回滚和使用移交。**不用Docker**，不依赖既有CAD容器，不迁移/停用几何或热服务，不修改shared-core业务，不提供无授权商业组件捆绑。

## 2. 前置依赖

B09 passed；候选代码、包、模板、字体hash有效。核查真实部署账户/目录/端口/Host连通性/安装权限及磁盘容量，不使用猜测端口；先完成隔离测试安装和可审查命令/差异，再按适用用户授权安装目标环境。当前“只制定计划”不等于已授权现在部署。

## 4. 接口、数据结构和兼容性约束

部署结构建议：独立release目录＋current链接、每release锁定venv；独立data目录包含SQLite、uploads、staging、artifacts；日志归systemd journal并脱敏。开发根不直接承载生产数据库。服务以专用无特权账户运行；API监听回环或经核查批准的内网接口，由DSH Host访问；不新增无认证公网端口。

配置至少包含 `HEATER_DATA_DIR`、`HEATER_TEMPLATE_DIR`、`HEATER_LISTEN_HOST/PORT`、`HEATER_SERVICE_TOKEN_FILE`、`HEATER_CONFIRMATION_KEY_FILE`、上传/解压/行数上限、worker超时、`HEATER_DWG_ENABLED` 与converter配置文件路径。真实密钥文件仅服务/Host账户可读；不要把密钥写进unit命令行或示例。模板/字体hash与B09一致，依赖路径不能跳入旧业务venv。

systemd分别管理API和单worker，明确WorkingDirectory/解释器/环境文件、Restart策略、Stop超时；启动后核查无遗留转换/Xvfb子进程。启用DWG时许可必须覆盖真实无人值守服务范围，独立安装/引用方式符合条款；否则保持disabled并明确DXF/PDF范围，不能把仅评估许可带入生产。

首版默认不自动删除已发布交付及原输入；临时目录仅清理已经终止且不再引用的run，保留诊断周期由运维确认。配置容量告警/拒绝新任务而不是悄悄删历史文件。备份必须一致包含DB、输入、产物、模板版本、配置（密钥另走受控保存），不能只拷贝运行中的SQLite主文件丢WAL。

数据库迁移有版本与兼容说明，回滚前备份；不支持逆迁移时恢复旧版本匹配快照，不强行让旧代码读新schema。变更current之前暂停接新任务并处理运行中任务，避免半包。

## 5. 可执行的验收步骤与通过条件

1. `.venv/bin/python scripts/preflight.py --config deploy/test-deployment.json --output docs/evidence/B10/preflight.json`：检查账户/路径/端口、Python/锁依赖、字体/模板、宿主连通、磁盘权限和DWG能力；不自动修改系统。配置文件不含密钥值。
2. `.venv/bin/python scripts/install_release.py --config deploy/test-deployment.json --dry-run --output docs/evidence/B10/install-plan.json`：输出可审查安装内容、unit、路径、升级/回滚动作；随后在已授权测试范围实装同一候选，并记录真实命令。
3. `systemd-analyze verify deploy/systemd/*.service`；在实际选定unit范围启动/重启API与worker后，通过 `/healthz`、`/readyz` 与DSH工作台检查，不停止旧服务。记录真实unit/user/port而不是文档示意值。
4. `.venv/bin/python scripts/smoke_deployed.py --config deploy/test-deployment.json --case fixtures/case/加热器图纸.xlsx --output docs/evidence/B10/smoke`：经DSH Host真实生成3页包，hash/集合核验通过；服务重启后任务/审阅历史可读，跨会话拒绝仍有效。
5. `.venv/bin/python scripts/backup_restore.py --config deploy/test-deployment.json --exercise-restore --output docs/evidence/B10/restore`：在独立临时恢复目录恢复一次，检查数据库与原件/产物hash；演练候选升级失败回到上一版，未覆盖生产数据。首次安装无上一版则演练卸载本新增单元/插件恢复安装前状态，保留数据。
6. 取得适用目标环境安装授权后部署同一候选；只安装本插件到确认账户/profile，复跑目标smoke并记录平台URL、服务版本和包hash。授权缺失则保留测试验证及待安装项为blocked，不临时冒充上线。
7. `.venv/bin/python scripts/verify_batch.py B10 --report-dir docs/evidence/B10`：测试与实际目标验收分列，目标未安装不能整体passed。使用指南包含导入/确认比例/错误修正或跳过/下载/人工复核及已知DWG限制。

通过：用户可在指定DSH使用、Linux服务可重启恢复、备份/回滚实测，依赖与权限明确，无Docker和旧业务运行依赖。只给systemd文件或压缩包不算部署验收。
