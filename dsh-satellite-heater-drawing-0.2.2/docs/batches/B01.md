# B01 — 独立项目、材料与契约基础

执行前阅读：[计划](../plan.md)、[契约](../contracts.md)、[需求](../reference/requirements.md)、[核查](../reference/project-baseline.md)、[进度](../progress.md)。本文及上述文件是完整任务说明，无需旧聊天。

## 1. 目标与明确的不做事项

在独立开发根建立最小可复现工程、保存真实案例、固化共享契约和验收框架，使后续 Batch 不依赖其他业务仓库。不得实现绘图/业务 UI，不启动生产服务、不安装 CAD 转换器、不修改 G/T/S/H 或喷漆多层项目。不得创建 Dockerfile/Compose。

## 2. 前置依赖

无开发前置。已有用户授权使用本地 `heater-drawing/docs/`；拟远端开发根见 plan §4。首先核查 SSH、适用 AGENTS、目录存在性、Git 状态；若有同名现有项目先比对，不覆盖。将本目录完整 docs 同步进新根，不能只复制 B01。原案例从 baseline 指定位置复制并按 source-files.json 核验。

## 3. 预计修改的模块和文件

全部为新根内新增：

- `README.md`、`.gitignore`、`service/pyproject.toml`、`service/uv.lock`、`.python-version`；独立 `.venv`，Python 3.12，package=`heater-drawing-service`、模块=`heater_drawing`。
- `service/src/heater_drawing/{__init__,config}.py`、`domain/models.py`；仅配置和数据结构。
- `schemas/{heater-row,revision,drawing-page,artifact,error}.schema.json`，`schemas/openapi.json`（先覆盖已定义契约的快照，标记未实现路由）。
- `fixtures/case/` 原文件副本、`fixtures/case/manifest.json`、`fixtures/case/expected.json`（从 R02 明确字段建立，不照抄错误 PDF）。
- `scripts/{verify_batch,check_source_boundary}.py`、`scripts/acceptance_registry.json`。
- `tests/contracts/test_models.py`、`tests/planning/test_runner.py`。
- `docs/reports/B01.md`、`docs/evidence/B01/`、`docs/progress.md`；后续 Batch 尚不存在的实现路径不创建假 stub 成功。

## 4. 接口、数据结构和兼容性约束

实施 C01/C02/C07。17字段映射、十进制字符串、UUID、schema_version=1、错误编码、revision hash 规范 JSON 序列化必须固定。形成 enum 和跨 Python/JSON Schema 一致测试；工具/路径/命令不得作为普通业务请求字段。

初始依赖选 FastAPI/Pydantic/openpyxl/ezdxf/Matplotlib/pypdf/pytest；具体版本以安装成功并锁文件为准，记录与既有环境的差别，不复制共享 venv。需构建 wheel 并验证 schema/template 运行时定位策略；正式模板 B02 后加入包或只读部署资源。

runner 采用 C07 退出语义。B01 registry 只登记真实已实现验收；未实现 Batch 返回 blocked。每个依赖报告绑定内容 hash。source boundary 只读记录旧项目 HEAD、Git 可见改动与相关参考文件 hash；不能要求其他项目因并行工作保持字节不变，发现差异时区分外部变化和本 Batch 越界，不回滚它们。

## 5. 可执行的验收步骤与通过条件

以下命令均在新开发根执行；B01 负责创建所有提到的脚本，不能在当前仅规划阶段声称已运行。

1. 使用 `uv venv .venv --python 3.12` 创建根环境，`source .venv/bin/activate` 激活；首次 `uv lock --project service` 生成锁，再 `uv sync --project service --frozen --active` 安装；保存解释器路径、包版本与锁文件 hash。后续恢复仅按既定锁安装，不能每次重新求解。若 uv 不可用，先选择并文档化等价锁定方式，不能退回共享环境。
2. `.venv/bin/python -m pytest -q tests/contracts tests/planning`：数字边界、未知字段、错误行定位、schema与模型一致、runner遇到失败/缺人工/零测试不报pass。
3. `.venv/bin/python scripts/check_source_boundary.py --output docs/evidence/B01/source-boundary.json`：只在新根新增；既有用户更改没有被覆盖。
4. `.venv/bin/python scripts/verify_batch.py B01 --report-dir docs/evidence/B01`：所有必需项通过；10个原件 hash 与 source-files.json 相同，expected 仅3行且O3=郑玲；根 README 能使下一聊天重建环境。
5. `git diff --check`；记录新根 Git HEAD/工作状态，不将父目录其他未跟踪文件一并提交。

通过：独立环境可重建、原件不变、契约一致、验收失败不会伪成功；报告写明初始化位置和后续统一命令。此批不要求任何出图结果。
